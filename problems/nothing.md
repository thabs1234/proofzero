# Nothing

**Status:** Not a problem
**Field:** Epistemology / the Foundations
**First stated:** TBD, apparently now
**Source:** This file

## No statement

There is no conjecture here. That is the entire content of the entry, and
the reason it is still an entry.

Every other file in this repository describes a *thing* — a definite
question with a definite answer that nobody currently possesses. This one
describes the shape of the hole those answers sit in. It is filed here to
make the absence visible and structured, which is the only kind of thing
this repository knows how to do.

## Why this file exists

Two reasons, and the second is the real one.

**The joke.** A repository called ProofZero, which solves nothing, ought to
contain an entry about nothing. Otherwise the name is a boast and not a
specification. The name promises exactly one deliverable, and this file is
where that deliverable is kept.

**The actual argument.** Nothing is not a failure of language. It is
nameable, and naming it is not the same as inventing it. Anyone can point at
the region of the theory where the answer to the Riemann Hypothesis is
supposed to be, describe its extent, bound what is known about it, and show
where the search has reached. Every other note in this repository does
exactly that and none of them produces the answer. They make an absence
into an object. That operation is the whole content of the idea, and it
does not require the absence to be solved for it to work.

The phrase that carries it: **the existence of the comprehensible.** To
comprehend a nothing is not to invent it. It is to hold a gap in view
without filling it in.

## Why there is no exhibit card

The other ten entries open with an exhibit card stating three things: what
is known, what a tool here checked, and what remains open. This file
deliberately does not have one.

There is nothing to bound. A bound requires a quantity, and the subject of
this entry is the absence of one. Writing "no bound" here would be the same
move as a bound — it would turn the absence into a positive claim, which is
precisely what the file is arguing against.

The four Millennium notes that ship no tool *do* carry cards, and they say
"no tool exists, and here is why." That is different from this file. Those
are problems for which no honest check is available. This is not a problem
at all, and the card format has nothing to say about it. Omitting the card
is the point, and if a future version of this repository adds one here, that
version has misunderstood the file.

## No notes, no references

There is no literature to cite. "Nothing" is not a term of art awaiting a
result; it is a word, and the observation that it is comprehensible is old
enough that attaching a citation to it would be theatre.

If this entry ever acquires a bibliography, it has stopped being what it is.

## What this is not

- It is not a proof that any conjecture is unprovable.
- It is not a claim that the ten problems are unsolvable, or that effort on
  them is wasted. Perelman solved one; that is precisely why the other six
  are still worth a repository.
- It is not a philosophical position being argued. There is no opposing
  view being refuted here, which is unusual for a document in a folder
  called `problems/`.

It is a label on an empty shelf, and the label is legible.

## The honest test

If this file made the repository look more productive, it would be
failing. A reader who finishes this note should feel slightly *less* impressed
with the repository than when they started, having been reminded that ten
entries of tidy structure have produced zero results — and that the structure
was the deliverable all along.

Compare [`poincare-conjecture.md`](millennium-prize/poincare-conjecture.md),
where the answer exists. That is what a solved problem looks like: a name, a
proof, a date, a prize declined. Everything in this repository that does not
reach that state is, at present, this file with more words on it.
